# Certificate background jobs and recovery

AD CS connection tests, enrollment and pending collection run in the finite diagnostic worker queue. Web admission validates local profiles and request fields; key generation and network traffic happen in the worker. Existing diagnostic worker, queue, per-user, history and deadline settings apply. Imported RSA PEM keys have a 16 KiB envelope; supported sizes remain 2048, 3072 and 4096 bits.

Before enrollment submits to the CA, the job durably stores its private key and CSR in encrypted progress and then records submission intent. An observed CA request ID/disposition is saved before certificate retrieval. Known pending or issued acknowledgements register a pending certificate version with the matching key; a unique internal operation ID prevents duplicate local versions. Retrieval validates the certificate key and requested names. Completion requires the exact current pending version and matching request ID.

Enrollment and collection jobs serialize per instance. The worker rechecks the saved server, credential, template and current certificate revisions before the applicable remote operation. An interrupted submission is never automatically replayed. Cancellation or timeout after submission can leave the CA request active; toolkit cancellation does not revoke a certificate or cancel CA processing. If the CA outcome cannot be confirmed, the job becomes **unknown** and retains its encrypted recovery key, CSR, issuer/template context and any observed request ID. Another enrollment for the same managed certificate or new-certificate name is blocked until reconciliation.

The workspace has ten recent requests and a separately paged unresolved-submission list (20 per page). Job pages and recovery downloads require the original owner and current Certificate Automation access. Status JSON and HTML do not contain credentials, private keys or CSRs. Recovery key/CSR downloads are explicit, uncached and audited. If registration completed before interruption, the job links to its saved certificate/request. Reconcile the CA state and preserve needed recovery material before checking the acknowledgement box and discarding the job's recovery material. This does not delete an already registered managed certificate or resubmit any request.

Unknown enrollment records are excluded from both age and count pruning, but still count against the existing history capacity. If unresolved records fill that capacity, admission fails until an owner reconciles records. They are not silently deleted to make room. Ordinary terminal jobs follow normal retention. Enrollment passwords, imported-key input and passphrases are encrypted while needed and removed from terminal job configuration when the worker releases ownership (or during recovery/cleanup). Unknown recovery key/CSR material remains separately encrypted until explicit reconciliation. The matching instance key must be preserved in backups.

The browser locks a submitted form until queue acknowledgement, preserves its draft and file/password inputs after failure, and clears sensitive fields only on acknowledgement. It stays on the workspace with a result link so unrelated drafts survive. A request nonce and keyed receipt binding suppress duplicate admission for the same retained submission. If acknowledgement is lost, check recent requests before retrying. Without JavaScript, successful admission redirects to the retained job; validation failures return an error without reflecting secrets.

Results distinguish CA pending/denied dispositions from issuance. The original actor and recording case are retained; secondary recording failures produce a visible warning and never trigger replay. Provider sessions are closed, and job-owned temporary CA files are reclaimed after worker ownership ends by diagnostic cleanup. These jobs do not change ACME execution, revoke certificates, impose a global PKI traffic budget, or complete native appliance/platform acceptance.
